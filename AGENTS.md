# Delivery rules

- Treat every website change as a presentation-ready production delivery for the client.
- Never expose internal production notes, placeholder copy, approval status, or labels such as “fotografía referencial”, “imagen referencial”, “pendiente de aprobación”, or equivalent wording in customer-facing UI, metadata, or accessibility text.
- When information is not ready or confirmed, omit it from the public interface instead of showing a caveat. Keep any necessary follow-up only in internal documentation.
- Treat “commit”, “push” and “deploy” as authorization to commit the requested changes and publish them to GitHub, unless the user explicitly says to keep the work local.
